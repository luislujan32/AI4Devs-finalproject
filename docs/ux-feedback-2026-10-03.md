# Revisión UX del recorrido de screening — 03/10/2026

Las capturas C1–C8 y la prueba de Luis muestran dos recorridos: autoría del screening y operación con postulantes. La invitación no pertenece a cada paso de autoría. Se adoptó una navegación superior Configuración / Postulantes para screenings publicados; en borrador solo aparece la configuración. Esta agrupación sigue el principio de tareas relacionadas y estados claros del [patrón de múltiples tareas de GOV.UK](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/). Es una inferencia para este producto, no una plantilla que deba copiarse literalmente.

La [revisión de respuestas de GOV.UK](https://design-system.service.gov.uk/patterns/check-answers/) respalda mostrar lo declarado y facilitar la edición antes del envío. Su [patrón de confirmación](https://design-system.service.gov.uk/patterns/confirmation-pages/) orienta a un recibo claro tras la operación, sin repetir mensajes de éxito. El [patrón de tooltip W3C](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) describe aparición por hover/foco y cierre con Escape; aquí se añadió activación por toque para móviles. Estas referencias informan decisiones de diseño: la prueba con usuarios todavía falta.

## Segunda prueba de Luis: mejoras aplicadas y propuestas pendientes

Las capturas posteriores confirman que el correo inicial, el guardado al enviar y la separación de Postulantes mejoraron el recorrido. Luis propuso seguir refinando los estados, el correo, el acceso, el recibo y las acciones una vez recibidas las respuestas. Estas observaciones no autorizan por sí solas a cambiar el contrato de acceso sin definir el flujo completo.

**Estados de invitación (C1).** Se añadieron fondos suaves: «Por responder» neutro, «En curso» informativo y «Respuestas recibidas» destacado. El badge conserva texto y no parece botón. En T-08, una acción separada «Ver respuestas» lleva al informe, sin confundir recepción con decisión humana. Falta observar contraste y comprensión con usuarios. [GOV.UK Tag](https://design-system.service.gov.uk/components/tag/) recomienda etiquetas no interactivas y pocos estados; [Atlassian Lozenge](https://atlassian.design/components/lozenge) aporta semántica de color según el tipo de estado.

**Acceso desde correo o enlace compartido (C3).** Actualmente ambos contienen el mismo `publicId`; el sistema no puede inferir con seguridad si se hizo clic en el correo o se pegó un enlace copiado. La propuesta es emitir dos credenciales diferentes: un enlace de correo personal, de un uso y duración corta, que abre la sesión del candidato; y un enlace compartible que continúa requiriendo verificar el correo. Si el enlace de correo vence o ya se usó, la persona podrá solicitar uno nuevo sin perder su intento. Un enlace reenviado puede abrirlo otra persona: esto acredita posesión del enlace, no identidad civil. El código enviado al **mismo** correo no constituye un segundo factor independiente. Antes de implementarlo hay que definir expiración, reenvío, reanudación, consumo atómico, filtración de URL y recuperación. [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) recomienda tokens de URL aleatorios, de un uso y con vencimiento; [NIST](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) distingue validación del correo de autenticación multifactor. Esta es una propuesta para mejorar UX, no una afirmación de cumplimiento de esos estándares.

**Después del envío (C5/C6).** El candidato ve una confirmación con fecha e imposibilidad de editar, sin evaluación ni decisión automática. El enlace original puede reabrir el recibo mientras la invitación esté vigente. En T-08, la fila `submitted` dejó de mostrar «Copiar enlace» y ofrece «Ver respuestas». El texto del recibo sigue abierto a una prueba de comprensión. [GOV.UK Confirmation pages](https://design-system.service.gov.uk/patterns/confirmation-pages/) recomienda explicar qué pasará después de completar el trámite.

**Correo (C2).** La presentación inicial funciona como base. Revisar más adelante asunto, tono, nombre del puesto, plazo y ayuda para problemas de acceso con una prueba de comprensión; no prometer un plazo de revisión que el producto aún no puede garantizar.
